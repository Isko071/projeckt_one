# Заготовка под мультиплеер

Сейчас игры одиночные или «вдвоём на одном устройстве». Чтобы «Ятзи», блэкджек и покер позже можно было играть по сети, без переписывания правил, вводятся три договорённости. Сети и сервера пока **нет**: это каркас и тесты.

## 1. Игра = три чистые функции

```js
game = {
  init(seats, options, rng) → state,
  reduce(state, action, rng) → { ok: true, state, events } | { ok: false, error },
  view(state, seat) → то, что видит это место     // скрытая информация: карты соперников, колода
}
```

- `reduce` **не меняет** состояние на месте, а возвращает новое.
- Каждое действие несёт место `seat`; `reduce` сам проверяет, чей ход и допустимо ли действие. Поэтому серверу достаточно переслать действие в `reduce`, доверять клиенту не нужно.
- Случайность берётся только из переданного `rng`.
- Состояние и действия — простые данные (JSON): их можно хранить и пересылать.

## 2. Сессия (`shared/game-session.js`)

`PlatformSession.create({ game, seats, seed, transport })`:

- **Места за столом**: `{ id, name, kind: 'human' | 'cpu' | 'remote' }`. Компьютер и удалённый игрок — такие же места, как человек, отличается только источник действий.
- **Журнал действий**: любую партию можно воспроизвести (`PlatformSession.replay`) из `seed` и журнала. Это основа проверки честности, повтора партии и восстановления после обрыва связи.
- **Детерминированный генератор** (`createRng(seed)`): у всех участников одинаковые броски и раздачи, если seed общий. В настоящей сетевой игре seed и раздачи делает сервер, а не клиент.
- **Транспорт** `{ send(entry), onRemote(fn) }`: через него действия уходят и приходят. По умолчанию его нет, всё применяется на месте.
- `viewFor(seat)` отдаёт каждому месту только его данные.

## 3. Состояние игры

Сейчас готово для «Ятзи»: `games/yahtzee/actions.js` добавляет `Yahtzee.reduce` и `Yahtzee.view`, действия `roll`, `toggleHold`, `score`. Текущий интерфейс пока работает напрямую с `logic.js`; перевод его на сессию — отдельный шаг, когда понадобится сеть или повторы.

Блэкджек и покер сразу пишутся в этой форме:
- `view` прячет закрытые карты дилера и соперников и колоду;
- ставки идут через общий кошелёк, но в сетевой партии списание и выплату делает сервер;
- у покера до 6–9 мест, у блэкджека до 5.

## Онлайн-столы без сервера

Для блэкджека сделан первый вариант: комнаты в Firestore, ведущий игры — браузер создателя стола. Описание, правила базы и ограничения: [онлайн-столы](online-tables.md).

## Что понадобится для настоящего мультиплеера (не сделано)

1. Сервер или сервис с комнатами, который хранит сессию и вызывает те же `reduce` и `view`.
2. Транспорт (WebSocket или готовый сервис реального времени).
3. Аккаунты: чьё место за столом (см. [архитектуру](architecture.md#профиль-и-аккаунты)).
4. Таймеры хода, отключение и возвращение игрока, лобби.
