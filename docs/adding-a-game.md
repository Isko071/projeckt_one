# Как добавить новую игру

Инструкция для любой следующей игры (сапёр, блэкджек, покер и дальше). Структура и договорённости описаны в [архитектуре](architecture.md); здесь только порядок действий.

> Как и вся документация платформы, это план: шаблон и общие файлы появятся на этапе 1–2 ([дорожная карта](roadmap.md)).

## Коротко

1. Создать папку `games/<id>/` по шаблону.
2. Написать чистую логику и тесты.
3. Сделать интерфейс на общей теме.
4. Добавить обложку и тексты.
5. Внести игру в реестр `games/games.js`.
6. Проверить по списку в конце.

## 1. Папка по шаблону

`<id>` — короткое имя латиницей без пробелов (`minesweeper`, `blackjack`, `poker`). Оно же имя папки и ключ в реестре и словаре.

```
games/<id>/
├── index.html        # страница игры
├── logic.js          # чистые функции правил (без DOM и без случайности «внутри»)
├── ui.js             # интерфейс, обработчики, анимации
├── style.css         # стили игры поверх общей темы
├── cover.svg         # обложка для каталога
└── tests/
    └── logic.test.js # автотесты логики
```

В `index.html` подключаются общие файлы платформы и файлы игры (обычными `<script>`, без модулей):

```html
<link rel="stylesheet" href="../../shared/theme.css">
<link rel="stylesheet" href="style.css">

<script src="../../locales/ru.js"></script>
<script src="../../shared/storage.js"></script>
<script src="../../shared/theme.js"></script>
<script src="../../shared/profile.js"></script>
<script src="../../shared/i18n.js"></script>
<script src="logic.js"></script>
<script src="ui.js"></script>
```

На странице должна быть кнопка «В каталог» со ссылкой `../../index.html`.

## 2. Логика и тесты

- Правила игры — **чистые функции**: на тех же входных данных всегда тот же результат. Случайность (кубики, колода, мины) передаётся параметром (`rng`), чтобы тесты были воспроизводимыми.
- Всё состояние игры лежит в **одном объекте**.
- Тесты запускаются командой `node --test games/<id>/tests/`. Логика подключается в тесте так же, как в «Ятзи»: файл читается и выполняется в `vm` (поэтому в `logic.js` не должно быть обращений к `window`/`document`).
- Что покрыть тестами: все правила подсчёта и победы, граничные случаи, конец игры, поведение компьютерного соперника (если он есть).
- Если в игре есть компьютерный соперник, сравните его с простым вариантом симуляцией на одинаковых бросках/раздачах: «сильный» должен заметно выигрывать у «лёгкого».

## 3. Интерфейс

- Используйте токены из `shared/theme.css` (`--bg`, `--surface`, `--ink`, `--muted`, `--line`, `--accent` и остальные), а не свои цвета для базовых элементов. Тогда светлая и тёмная темы и общий переключатель работают сами.
- Игра должна быть удобна на телефоне (ширина от 320 px) и на десктопе, без горизонтальной прокрутки.
- Все анимации учитывают `prefers-reduced-motion`.
- Интерактивные элементы — настоящие `<button>`/`<input>` с подписями (`aria-label`) и видимым фокусом.
- Имя игрока берётся из профиля (`getProfile()`), а не вводится заново без необходимости.
- Данные игры (рекорды, настройки, банк фишек) хранятся только через `shared/storage.js` с ключами `game:<id>:…`.
- Для игр с фишками: только виртуальные фишки, пометка «без реальных денег», возможность сбросить банк.

## 4. Обложка и тексты

**Обложка** — `games/<id>/cover.svg` (или растровая картинка), единый размер и пропорции по макету из Claude Design. Пока макета нет, используется временная плашка с названием игры.

**Тексты** — в словарь `locales/ru.js` добавьте ключи:

```js
'games.<id>.title': 'Название игры',
'games.<id>.description': 'Короткое описание для главного постера (1–3 предложения).'
```

Остальные надписи самой игры — по ключам `games.<id>.*` в том же словаре или в словаре игры. Не вшивайте русские строки прямо в код: так позже можно добавить другие языки.

## 5. Реестр

Добавьте запись в `games/games.js`:

```js
{
  id: '<id>',
  status: 'soon',                 // пока игра не готова
  path: 'games/<id>/',
  cover: 'games/<id>/cover.svg',
  titleKey: 'games.<id>.title',
  descriptionKey: 'games.<id>.description'
}
```

Когда игра готова, поменяйте `status` на `'available'`. Больше в каталоге ничего менять не нужно.

## 6. Список проверки перед слиянием

- [ ] Папка `games/<id>/` соответствует шаблону.
- [ ] Логика чистая, тесты проходят: `node --test games/<id>/tests/`.
- [ ] `node --test tests/registry.test.js` проходит (поля заполнены, файлы существуют).
- [ ] В светлой и тёмной темах всё читается, переключатель темы работает.
- [ ] Нет горизонтальной прокрутки на 320 px и на широком экране.
- [ ] Игра запускается из каталога и отдельно (открытием `games/<id>/index.html`).
- [ ] Кнопка «В каталог» работает.
- [ ] Хранилище недоступно (например, в приватном режиме): игра не падает.
- [ ] Тексты в словаре, а не в коде.
- [ ] Для игр с фишками: только виртуальные фишки, есть пометка.
- [ ] Описание в реестре и README платформы обновлены (таблица игр).

## Порядок работы над игрой

Как и всё остальное: по этапам с отдельным коммитом на каждый и подтверждением перед следующим.

1. Логика и тесты.
2. Интерфейс.
3. Подключение к каталогу (реестр, обложка, тексты).
4. Дополнительно (компьютерный соперник, анимации, правила).
