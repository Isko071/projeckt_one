# Архитектура

Документ описывает, как мы собираемся устроить платформу. Это план, а не описание готового кода.

## Принципы

1. **Статический сайт без сборки.** Только HTML, CSS и JavaScript. Открывается двойным кликом и публикуется на любом статическом хостинге.
2. **Обычные скрипты, без ES-модулей.** Модули (`import`) не работают при открытии файла с диска (`file://`) в части браузеров. Обычные подключаемые скрипты работают везде и не требуют сервера для разработки.
3. **Каждая игра независима.** Живёт в своей папке, запускается и сама по себе, и из каталога. Каталог не знает внутренностей игры.
4. **Общее — отдельно.** Тема, язык, профиль, хранение данных и стили вынесены в `shared/`, чтобы не копировать их в каждую игру.
5. **Чистая логика отдельно от интерфейса.** Правила игры — чистые функции, которые тестируются через `node --test` (как в «Ятзи»).
6. **Хранилище браузера ненадёжно.** Каждое чтение и запись `localStorage` обёрнуты в `try/catch`; без хранилища всё работает, просто ничего не запоминается.
7. **Без реальных денег.** В играх только виртуальные фишки.

## Структура репозитория

```
/
├── index.html              # каталог игр (главная страница)
├── catalog/
│   ├── catalog.css         # стили каталога и главного постера
│   └── catalog.js          # отрисовка списка, выбор игры, переходы
├── games/
│   ├── games.js            # реестр игр (единый список с описаниями)
│   ├── yahtzee/            # игра «Ятзи»
│   │   ├── index.html
│   │   ├── logic.js        # чистые функции
│   │   ├── ui.js
│   │   ├── style.css
│   │   ├── ru.js           # тексты игры (games.yahtzee.*)
│   │   ├── cover.svg       # обложка для каталога
│   │   └── tests/          # logic.test.js, texts.test.js
│   ├── minesweeper/        # то же самое
│   ├── blackjack/
│   └── poker/
├── shared/
│   ├── theme.css           # цветовые токены (светлая и тёмная тема)
│   ├── theme.js            # переключатель темы и запоминание выбора
│   ├── storage.js          # безопасная обёртка над localStorage
│   ├── profile.js          # локальный профиль (имя, аватар)
│   └── i18n.js             # выбор языка и подстановка текстов
├── locales/
│   └── ru.js               # словарь русских текстов
├── assets/                 # логотип платформы, иконки, аватары
├── docs/                   # документация
└── tests/
    └── registry.test.js    # проверяет, что реестр игр заполнен правильно
```

Имена файлов ориентировочные; важны границы: каталог, реестр, общее, игры.

## Каталог

### Экраны и поведение

1. **Список.** Сразу после открытия виден только список игр: сетка карточек (обложка, название). Главного постера нет.
2. **Выбор игры.** Нажатие на карточку «разворачивает» её в **главный постер** над списком: большая обложка, название, описание, кнопка «Играть». Остальные игры остаются в сетке ниже. Нажатие на другую карточку меняет главный постер.
3. **Закрытие постера.** Кнопка «закрыть» (и клавиша Escape) возвращает вид «только список».
4. **Запуск.** Кнопка «Играть» открывает страницу игры `games/<id>/`.
5. **Состояние в адресе.** Выбранная игра хранится в хеше ссылки (`#yahtzee`). Так работают кнопка «Назад» и прямая ссылка на постер игры.
6. **Игры «скоро».** Игры со статусом `soon` показываются в сетке с пометкой «Скоро», кнопка «Играть» неактивна.

### Шапка

- Логотип и название платформы (клик возвращает к списку).
- Кнопка смены темы (светлая/тёмная).
- Аватар/профиль: имя и картинка игрока, меню с настройкой профиля.

### Адаптивность

- Телефон: сетка из 2 колонок, главный постер вертикальный (обложка над описанием).
- Планшет и десктоп: сетка из 3–5 колонок, главный постер горизонтальный (обложка слева, текст справа).
- Постер и сетка не требуют горизонтальной прокрутки на любой ширине.

## Реестр игр

Каталог строит весь вид из одного списка — реестра `games/games.js`. Добавить игру значит добавить в реестр одну запись.

```js
// games/games.js
window.GAMES = [
  {
    id: 'yahtzee',               // латиницей, совпадает с именем папки
    status: 'available',         // 'available' | 'soon'
    path: 'games/yahtzee/',      // папка игры; «Играть» ведёт на path + 'index.html'
    cover: 'games/yahtzee/cover.svg',
    titleKey: 'games.yahtzee.title',
    descriptionKey: 'games.yahtzee.description'
  },
  { id: 'minesweeper', status: 'soon', path: 'games/minesweeper/', cover: 'games/minesweeper/cover.svg',
    titleKey: 'games.minesweeper.title', descriptionKey: 'games.minesweeper.description' }
];
```

Обязательные поля: `id`, `status`, `path`, `cover`, `titleKey`, `descriptionKey`. Автотест `registry.test.js` проверяет, что поля есть, `id` уникальны, а файлы обложек и страниц существуют.

В главном постере по решению показываются обложка, название и описание. Теги, число игроков и рейтинг можно добавить позже, не ломая реестр (новые необязательные поля).

## Договорённости между каталогом и игрой

Игра — самостоятельная страница. От неё требуется немного:

1. **Подключить общие стили и скрипты** (`shared/theme.css`, `shared/theme.js`, `shared/storage.js`, `shared/profile.js`, `shared/i18n.js`), чтобы тема, язык и имя игрока были общими.
2. **Кнопка «В каталог»** со ссылкой на корень платформы (`../../index.html`). Если игра запущена отдельно, ссылка просто ведёт на главную.
3. **Хранить свои данные в своём пространстве** (см. ниже) и только через `storage.js`.
4. **Не ломать общую тему.** Использовать токены `--bg`, `--surface`, `--ink`, `--accent` и остальные из `theme.css`, а свои цвета объявлять поверх, не заменяя.
5. **Тексты через словарь.** Надписи берутся из `locales/ru.js` по ключам `games.<id>.*`.
6. **Чистая логика отдельно** от интерфейса и с тестами.

### Как переехал «Ятзи» (этап 4)

- Один файл `index.html` разделён на `games/yahtzee/index.html`, `logic.js` (чистая логика, тестируется через `vm`), `ui.js`, `style.css` и `ru.js` (тексты игры, ключи `games.yahtzee.*`); тесты переехали в `games/yahtzee/tests/` и дополнены проверкой текстов.
- В игре кнопка «В меню» превратилась в «В каталог» (в незаконченной партии с подтверждением, после конца партии без вопроса). На стартовом экране игры (выбор режима) рядом с кнопкой темы появился значок-ссылка на каталог. Внутренний выбор режима и сложности остался: открытие игры из каталога всегда начинается с него.
- Тема берётся из общего модуля платформы (`platform:theme`); собственный переключатель темы игры остался, но работает через `shared/theme.js`, поэтому выбор общий для каталога и игры. Прежний ключ `yahtzee-theme` не используется.
- Имя первого игрока по умолчанию берётся из профиля (`getProfile().name`), поле имени можно изменить.
- Цвета игры: общие токены из `shared/theme.css`, а специфичные для неё (кубики, точки, подсветка, собственная тень `--game-shadow`) объявлены в `style.css` поверх, не заменяя общие.
- В `ui.js` нет русских строк: все надписи берутся через `tr('ключ')` из словаря игры (автотест следит за этим).

## Хранение данных

Всё в `localStorage`, через обёртку `shared/storage.js` (чтение и запись в `try/catch`, JSON внутри). Ключи с префиксами:

| Ключ | Что хранит | Кто пишет |
|---|---|---|
| `platform:theme` | `light` или `dark` (нет ключа — по системе) | платформа |
| `platform:lang` | код языка, пока только `ru` | платформа |
| `platform:profile` | имя и аватар игрока | платформа |
| `platform:sync` | отпечаток последней синхронизации с облаком (см. [вход через Google](google-login.md)) | платформа |
| `platform:wallet` | аконы, серия дней, журнал (см. [кошелёк](wallet.md)) | платформа (игры через `PlatformWallet`) |
| `game:<id>:*` | всё, что нужно игре (рекорды, настройки, банк фишек) | эта игра |

Игра не читает и не пишет чужие ключи. Если хранилище недоступно, обёртка возвращает значения по умолчанию и тихо ничего не запоминает.

**Ограничение:** `localStorage` живёт в одном браузере на одном устройстве. Общий рейтинг, синхронизация между устройствами и вход с паролем так не сделать — для этого нужны настоящие аккаунты (см. ниже).

## Тема

- Цвета описаны токенами в `shared/theme.css` (взяты из «Ятзи»: мягкий фон, зелёный акцент).
- Без явного выбора тема следует системной (`prefers-color-scheme`).
- Кнопка в шапке выставляет явный выбор: `data-theme="light"` или `"dark"` на `<html>` и сохраняет его в `platform:theme`.
- Выбор общий для каталога и всех игр.
- Все анимации учитывают `prefers-reduced-motion`.

## Язык

- Сейчас только русский.
- Тексты не зашиваются в разметку и код, а лежат в словаре `locales/ru.js` по ключам (`catalog.title`, `games.yahtzee.description`, …).
- `shared/i18n.js` подставляет тексты по ключам. Чтобы добавить английский, нужно добавить `locales/en.js` с теми же ключами и переключатель; код менять не придётся.
- Игры могут держать свои тексты в словаре игры, но по тому же принципу.

## Профиль и аккаунты

### Этап 1: локальный профиль

- Имя (до 20 символов) и аватар (один из 8 цветных кружков с первой буквой имени) хранятся в браузере (`platform:profile`), пароля нет. Без хранилища профиль меняется до перезагрузки страницы.
- Игры берут имя оттуда (например, имя первого игрока в «Ятзи»).
- Всё обращение к профилю идёт через `shared/profile.js`: `getProfile()`, `saveProfile()`. Остальной код не знает, где данные лежат физически.

### Этап 2: настоящие аккаунты (позже)

В isko-three «вход» — это проверка наличия cookie `token`, которую может поставить любой пользователь, поэтому она ничего не защищает. Чтобы вход был безопасным, проверка пароля должна происходить на сервере, а не в браузере.

Планируется **готовый сервис аккаунтов** (например Supabase или Firebase Auth), без собственного сервера:

- пароли и сессии хранит и проверяет сервис, мы их никогда не видим и не храним;
- в репозитории не лежит ни одного секрета (публичные ключи клиента допустимы, секретные — нет);
- права доступа к данным игроков задаются правилами на стороне сервиса (каждый видит и меняет только свои записи);
- сайт отдаётся только по HTTPS.

Благодаря обёртке `profile.js` переход на аккаунты заменит только внутренности профиля. Выбор сервиса — открытый вопрос.

## Игры с фишками (покер, блэкджек)

- Только виртуальные аконы: никаких платежей, реальных денег и покупок.
- Баланс общий для всех игр и хранится в кошельке платформы ([кошелёк](wallet.md)), игры работают с ним через `PlatformWallet`; сбросить его можно в окне «Кошелёк».
- Пометок вроде «виртуальные аконы, без реальных денег» на экранах не делаем.
- Общий код колоды карт и фишек можно вынести в `shared/`, когда появится вторая карточная игра (блэкджек и покер).

## Мультиплеер

Игры пишутся в форме `init / reduce / view`, поверх которой работает `shared/game-session.js`. Подробнее: [заготовка под мультиплеер](multiplayer.md).

## Тесты

- Логика каждой игры: `node --test games/<id>/tests/*.test.js` (в Node 22 нужна маска, папку целиком передать нельзя).
- Каталог, реестр игр, профиль и общие модули: `node --test tests/*.test.js`.
- Интерфейс проверяется вручную и скриптами в headless-браузере при разработке; в репозиторий они не входят, если не понадобятся.
