# Онлайн-столы (блэкджек)

Режимы блэкджека: **«С ботом»** (вы один против дилера-бота) и **«Онлайн»** (стол на 2–5 игроков). Своего сервера нет, поэтому онлайн-стол устроен так:

- **Комната** — запись в Firestore (`rooms/<код>`, код из 5 символов). Игрок входит по коду или из списка открытых столов (`listRooms`).
- **Ведущий игры — браузер создателя стола (хост).** Он держит полное состояние (колоду и закрытую карту дилера), принимает действия игроков, прогоняет их через `reduce` игры и публикует в комнату только «вид стола» (`view`): без колоды и закрытой карты. Ходит за ботов, раздаёт, начинает следующую раздачу, по таймеру делает «стоп» или пропуск за молчащих (см. ниже).
- **Игроки** раз в секунду читают комнату и шлют действия отдельными записями `rooms/<код>/actions/*`. Хост читает их, применяет и удаляет. Место за столом определяет хост, а не игрок; допустимы только `bet`, `hit`, `stand` (в будущем `double`, `split`), `sitout` и `here` (ответ «играю»); раздача, новая раздача и посадка — только у хоста.
- Интерфейс: `games/blackjack/ui.js` (выбор режима, столы, комната ожидания, стол, вопрос «Вы ещё играете?»), макет Claude Design по промтам `prompts/design-blackjack*.md`. Проверка в браузере: два окна (создатель и игрок) против поддельного Firestore.
- Код: `shared/rooms.js` (`PlatformRooms`), игра: `games/blackjack/logic.js` (до 5 мест, боты, `join`, `leave`, `timeout`, `waitingSeats`), общий каркас: [мультиплеер](multiplayer.md). Тесты: `tests/rooms.test.js` (поддельный Firestore с теми же правилами).

## Ятзи онлайн (2–6 игроков)

Тот же принцип, но проще (`shared/rooms-turns.js`, логика стола `games/yahtzee/table.js`, интерфейс `games/yahtzee/online.js`): комнаты лежат в той же коллекции `rooms` (поле `game` = `yahtzee`), правила Firestore те же. Ботов и подсадки посреди игры нет: присоединиться можно только пока стол в ожидании.

- **Режим выбирает создатель.** «Одновременно»: все бросают и записывают очки в своём темпе, но следующий раунд (следующая клетка) начинается, только когда очки записали все активные игроки; записавший ждёт остальных. «По очереди»: ходит один игрок, остальные ждут.
- Кубики у каждого свои, их видят все; броски делает хост, поэтому подтасовать нельзя. Фиксация кубиков копится на экране игрока и уходит вместе с броском (без задержки сети на каждое нажатие).
- Неактивный игрок: через 100 секунд ему показывается вопрос «Вы ещё играете?» на 20 секунд (вместе 2 минуты). «Да» начинает отсчёт заново; без ответа игрок сразу сдаётся и выбывает из-за стола. Ходов и записи очков за него никто не делает. Если остался один игрок, партия заканчивается.
- За партию онлайн награды аконами нет, засчитывается только начало партии (серия дней).

## Когда можно начать игру

Игра **сама не начинается**: её запускает создатель кнопкой «Начать игру». Кнопка становится доступна, когда за столом **2 игрока и больше** и прошло **20 секунд** после последнего входа или выхода (чтобы остальные успели зайти): каждый новый игрок запускает отсчёт заново, выход одного из двух отменяет его. В комнате ожидания у всех виден отсчёт «Начать можно через N с» (поле `startIn` в комнате, оставшиеся миллисекунды на момент публикации). Хост проверяет это условие и сам, поэтому раньше времени игру не начать. В блэкджеке с включёнными ботами создатель может начать сразу, даже один.

## Закрытый стол

При создании стола (в «Блэкджеке» и «Ятзи») можно включить «Закрытый стол». Такой стол не показывается в списке открытых столов, войти можно только по коду или ссылке-приглашению; в комнате ожидания у всех написано «Закрытый стол: только по коду или ссылке». Это поле `private` в документе комнаты. Важно: закрытость держится на том, что код из 5 символов трудно угадать (около 28 миллионов вариантов), правила Firestore по-прежнему разрешают вошедшим читать комнаты, поэтому это не защита паролем.

## Ссылка-приглашение и новая игра

- **Ссылка** вида `…/yahtzee/#K7M4Q` или `…/blackjack/#K7M4Q` ведёт сразу за стол: вошедший игрок попадает в комнату без нажатий, а не вошедший сначала видит «Для онлайна нужно войти» и после входа тоже заходит за стол. Если стола нет, показывается «Стол не найден». Адрес после этого очищается от кода, чтобы обновление страницы не пыталось зайти снова.
- **«Ятзи»: Играть снова.** После конца партии стол не закрывается: у создателя в окне итогов есть кнопка «Играть снова». Стол возвращается в комнату ожидания с тем же кодом и теми же игроками (вышедшие убираются), чат остаётся, начать можно сразу. Остальные игроки видят «Ждём, пока создатель начнёт новую игру или закроет стол» и сами переходят в комнату ожидания. Кнопка «К выбору стола» по-прежнему закрывает стол создателя.

## Чат

В зале ожидания и во время игры у онлайн-стола есть текстовый чат (план и решения: [чат](chat-plan.md)). Сообщения идут через хост: игрок шлёт действие `{ type: 'chat', text, cid }`, хост очищает текст (до 200 символов, без управляющих символов), проверяет частоту (не чаще одного сообщения в 0,8 с и не больше 20 в минуту на игрока), кладёт сообщение в журнал (последние 20) и публикует его в поле `chat` документа комнаты. Новым игрокам видны эти же 20 сообщений. Системные записи (вход, выход, начало игры, выбывание) хост добавляет сам. Отдельных чтений Firestore и новых правил чат не требует. Код: `shared/chat-logic.js` (логика), `shared/chat-ui.js` и `shared/chat.css` (общий интерфейс «Блэкджека» и «Ятзи»), тексты `chat.*` в `locales/ru.js`. Игрок может скрыть чат у себя и выключить подсказки о новых сообщениях (хранится в `localStorage`).

## Вход

Для онлайна нужен вход через Google (правила базы пускают в комнаты только вошедших). Гость играет в режиме «С ботом».

## Молчащий игрок

Дилер всегда компьютер: стол играет против него, игроки друг против друга не играют.

1. На ход или ставку даётся **30 секунд**.
2. Потом игроку показывается вопрос «Вы ещё играете?» на **7 секунд** (у остальных за его местом подпись «Не отвечает»).
3. «Да, играю» даёт ещё **15 секунд**. Без ответа за 7 секунд, а также если и в эти 15 секунд игрок ничего не сделал, автоматически ставится «стоп» (на ставке — пропуск раздачи).
4. После трёх таких автоматических ходов подряд игрок выбывает, место освобождается.

Хост публикует в комнате массив `timers` (место, этап `idle` / `asking` / `extended`, сколько миллисекунд осталось), а игрок отвечает действием `here`.

## Правила Firestore для комнат

Добавьте к правилам базы `(default)` (рядом с `users/{uid}`):

```
match /rooms/{code} {
  allow read: if request.auth != null;
  allow create: if request.auth != null && request.resource.data.hostUid == request.auth.uid;
  allow update: if request.auth != null && resource.data.hostUid == request.auth.uid
                   && request.resource.data.hostUid == request.auth.uid;
  allow delete: if request.auth != null && resource.data.hostUid == request.auth.uid;

  match /actions/{id} {
    allow create: if request.auth != null && request.resource.data.uid == request.auth.uid;
    allow read, delete: if request.auth != null
      && get(/databases/$(database)/documents/rooms/$(code)).data.hostUid == request.auth.uid;
  }
}
```

Игрок не может менять комнату, читать чужие действия и писать действия от чужого имени.

## Ограничения (важно знать)

- **Честность держится на хосте.** Хост видит колоду и закрытую карту. Для игры на аконы это приемлемо; для серьёзного соревнования игру надо перенести на сервер.
- **Если хост закрыл вкладку, стол закрывается** (игроки видят это по пропавшему сигналу за 30 секунд). Вкладка хоста должна оставаться открытой и видимой: в фоне браузер замедляет таймеры.
- **Бесплатная квота Firestore** (Spark): около 50 000 чтений и 20 000 записей в день на весь проект (цифры из сторонних источников, проверьте в консоли). Опрос раз в секунду: сессия из 4 человек на 30 минут около 7 000 чтений. Хватит на несколько столов в день; для большего нужен платный план или сервер с постоянным соединением.
- **Задержка 1–2 секунды** на каждое действие (опрос, а не мгновенная доставка).
- Брошенные комнаты остаются в базе; их можно чистить автоматически через правило TTL в консоли Firestore (поле со временем удаления) или вручную.
- Фишки у каждого игрока свои (его кошелёк): ведущий считает результат раздачи, а баланс игрок обновляет у себя.
