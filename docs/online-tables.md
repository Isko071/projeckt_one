# Онлайн-столы (блэкджек)

Режимы блэкджека: **«С ботом»** (вы и бот против дилера) и **«Онлайн»** (стол на 2–5 игроков). Своего сервера нет, поэтому онлайн-стол устроен так:

- **Комната** — запись в Firestore (`rooms/<код>`, код из 5 символов). Игрок входит по коду или из списка открытых столов (`listRooms`).
- **Ведущий игры — браузер создателя стола (хост).** Он держит полное состояние (колоду и закрытую карту дилера), принимает действия игроков, прогоняет их через `reduce` игры и публикует в комнату только «вид стола» (`view`): без колоды и закрытой карты. Ходит за ботов, раздаёт, начинает следующую раздачу, по таймеру делает «стоп» или пропуск за молчащих (см. ниже).
- **Игроки** раз в секунду читают комнату и шлют действия отдельными записями `rooms/<код>/actions/*`. Хост читает их, применяет и удаляет. Место за столом определяет хост, а не игрок; допустимы только `bet`, `hit`, `stand` (в будущем `double`, `split`), `sitout` и `here` (ответ «играю»); раздача, новая раздача и посадка — только у хоста.
- Код: `shared/rooms.js` (`PlatformRooms`), игра: `games/blackjack/logic.js` (до 5 мест, боты, `join`, `leave`, `timeout`, `waitingSeats`), общий каркас: [мультиплеер](multiplayer.md). Тесты: `tests/rooms.test.js` (поддельный Firestore с теми же правилами).

## Вход

Для онлайна нужен вход через Google (правила базы пускают в комнаты только вошедших). Гость играет в режиме «С ботом».

## Молчащий игрок

Дилер всегда компьютер: стол играет против него, игроки друг против друга не играют.

1. На ход или ставку даётся **30 секунд**.
2. Потом игроку показывается вопрос «Вы ещё играете?» на **7 секунд** (у остальных за его местом подпись «Не отвечает»).
3. «Да, играю» даёт ещё **15 секунд**. Без ответа за 7 секунд, а также если и в эти 15 секунд игрок ничего не сделал, автоматически ставится «стоп» (на ставке — пропуск раздачи).
4. После трёх таких автоматических ходов подряд игрок выбывает, место освобождается.

Хост публикует в комнате массив `timers` (место, этап `idle` / `asking` / `extended`, сколько миллисекунд осталось), а игрок отвечает действием `here`.

## Правила Firestore для комнат

Добавьте к правилам базы `igroteka-db` (рядом с `users/{uid}`):

```
match /rooms/{code} {
  allow read: if request.auth != null;
  allow create: if request.auth != null && request.resource.data.hostUid == request.auth.uid;
  allow update: if request.auth != null && resource.data.hostUid == request.auth.uid
                   && request.resource.data.hostUid == request.auth.uid;
  allow delete: if request.auth != null && resource.data.hostUid == request.auth.uid;

  match /actions/{id} {
    allow create: if request.auth != null && request.resource.data.uid == request.auth.uid;
    allow read, delete: if request.auth != null
      && get(/databases/$(database)/documents/rooms/$(code)).data.hostUid == request.auth.uid;
  }
}
```

Игрок не может менять комнату, читать чужие действия и писать действия от чужого имени.

## Ограничения (важно знать)

- **Честность держится на хосте.** Хост видит колоду и закрытую карту. Для игры на виртуальные аконы это приемлемо; для серьёзного соревнования игру надо перенести на сервер.
- **Если хост закрыл вкладку, стол закрывается** (игроки видят это по пропавшему сигналу за 30 секунд). Вкладка хоста должна оставаться открытой и видимой: в фоне браузер замедляет таймеры.
- **Бесплатная квота Firestore** (Spark): около 50 000 чтений и 20 000 записей в день на весь проект (цифры из сторонних источников, проверьте в консоли). Опрос раз в секунду: сессия из 4 человек на 30 минут около 7 000 чтений. Хватит на несколько столов в день; для большего нужен платный план или сервер с постоянным соединением.
- **Задержка 1–2 секунды** на каждое действие (опрос, а не мгновенная доставка).
- Брошенные комнаты остаются в базе; их можно чистить автоматически через правило TTL в консоли Firestore (поле со временем удаления) или вручную.
- Фишки у каждого игрока свои (его кошелёк): ведущий считает результат раздачи, а баланс игрок обновляет у себя.
